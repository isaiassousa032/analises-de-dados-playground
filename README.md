# 🧪 Laboratório de Análises de Dados

Repositório dedicado a **projetos curtos de análise de dados**, desenvolvidos como forma de prática contínua e experimentação com diferentes datasets, ferramentas, técnicas e abordagens analíticas.

Os projetos possuem escopo reduzido e duração aproximada de **1 a 5 dias**, permitindo realizar com maior frequência o ciclo completo de uma análise.

> **Pequeno no escopo, completo no raciocínio.**

---

## 🎯 Objetivo

Projetos médios e longos são importantes para desenvolver soluções mais completas, mas também exigem semanas ou meses de trabalho.

Este laboratório segue uma proposta diferente.

O objetivo é aumentar a frequência com que pratico o processo de:

```text
Entender os dados
      ↓
Formular perguntas
      ↓
Explorar e analisar
      ↓
Encontrar evidências
      ↓
Interpretar resultados
      ↓
Comunicar conclusões
```

Cada projeto funciona como um pequeno experimento analítico.

O foco não está na complexidade da solução, mas na **qualidade do raciocínio utilizado para transformar dados em informação**.

---

## 🔬 Como funciona

Cada projeto parte de um dataset e de um objetivo de prática.

Os datasets podem vir de:

- cursos e trilhas de estudo;
- datasets públicos;
- Kaggle;
- bases governamentais;
- exercícios anteriores;
- outras fontes abertas.

Alguns datasets deste laboratório foram originalmente utilizados em cursos de SQL, Power BI, Databricks e outras tecnologias.

Aqui, porém, eles podem ser revisitados de maneira independente: as perguntas são definidas novamente e a análise é conduzida como um projeto próprio.

---

## 🧰 Ferramentas

O laboratório não possui uma stack obrigatória.

Cada projeto pode utilizar a ferramenta mais adequada ao objetivo da análise ou à habilidade que está sendo praticada.

Entre elas:

- **Excel**
- **Google Sheets**
- **SQL**
- **PostgreSQL**
- **Python**
- **pandas**
- **NumPy**
- **Jupyter Notebook**
- **Power BI**
- **Power Query**
- **DAX**
- **Databricks**

Um projeto pode utilizar apenas uma ferramenta.

Outro pode combinar duas ou mais.

A complexidade técnica só é adicionada quando contribui para o objetivo da análise.

---

## 📊 Abordagens analíticas

Os projetos também são utilizados para experimentar diferentes formas de analisar dados.

Isso pode incluir:

- análise exploratória;
- análise descritiva;
- análise diagnóstica;
- análise temporal;
- comparação entre grupos;
- segmentação;
- análise de distribuições;
- análise de outliers;
- correlações;
- estatística descritiva;
- análise de indicadores;
- análise orientada a problemas de negócio;
- visualização e storytelling.

A intenção é não associar análise de dados a uma ferramenta específica.

O processo parte do **problema e das perguntas**, e não da tecnologia.

---

## 🧠 Framework de análise

Os projetos utilizam como referência o **Framework de Análise de Dados — Lite**, uma metodologia reduzida para estruturar análises curtas sem adicionar documentação excessiva.

O processo é dividido em cinco etapas:

```text
Entender
   ↓
Perguntar
   ↓
Analisar
   ↓
Interpretar
   ↓
Concluir
```

O framework ajuda a definir:

- problema;
- granularidade;
- unidade de análise;
- fatos, dimensões e métricas;
- perguntas analíticas;
- hipóteses;
- evidências;
- interpretações;
- conclusões;
- limitações.

Para análises maiores e projetos end-to-end, utilizo uma versão mais completa do framework.

## 📁 Estrutura dos projetos

A estrutura pode variar de acordo com a ferramenta utilizada.

Um projeto com Python, por exemplo:

```text
01_nome-do-projeto/
│
├── README.md
├── data/
│   └── dataset.csv
│
└── analysis.ipynb
```

Um projeto em SQL:

```text
02_nome-do-projeto/
│
├── README.md
├── data/
│   └── dataset.csv
│
└── analysis.sql
```

Um projeto em Excel:

```text
03_nome-do-projeto/
│
├── README.md
├── data/
│   └── dataset.csv
│
└── analysis.xlsx
```

A estrutura deve permanecer proporcional ao tamanho do projeto.

> Um projeto curto não precisa da arquitetura de um projeto grande.

---

## 📝 Documentação

Cada projeto deve registrar, no mínimo:

1. **Objetivo** — O que quero descobrir?
2. **Dataset** — Quais dados estão sendo utilizados?
3. **Ferramentas** — Como a análise foi realizada?
4. **Perguntas** — O que quero responder?
5. **Análise** — Quais evidências foram encontradas?
6. **Conclusões** — O que os resultados permitem concluir?
7. **Limitações** — O que os dados não permitem afirmar?

A documentação deve ser suficiente para explicar o raciocínio sem transformar o projeto em um processo burocrático.

---

## ⏱️ Escopo

Os projetos deste laboratório são planejados para durar aproximadamente:

**1 a 5 dias.**

O objetivo não é explorar tudo o que pode ser feito com determinado dataset.

Um projeto é considerado concluído quando suas perguntas principais foram respondidas com evidências suficientes.

> **Novas perguntas não precisam aumentar o projeto atual. Elas podem se tornar o próximo experimento.**

Caso uma análise cresça significativamente em escopo, ela pode ser transformada em um projeto independente.

## 🌱 O que pretendo desenvolver

Mais do que acumular projetos, este laboratório existe para desenvolver prática.

Ao repetir o ciclo analítico com diferentes problemas e datasets, busco melhorar progressivamente minha capacidade de:

- compreender novos dados;
- identificar problemas de qualidade;
- formular boas perguntas;
- selecionar métricas relevantes;
- escolher técnicas adequadas;
- comparar resultados corretamente;
- identificar padrões;
- interpretar evidências;
- reconhecer limitações;
- comunicar conclusões de maneira clara.

---

## 💡 Princípio do laboratório

Este repositório não busca transformar todo dataset em um grande projeto de portfólio.

Ele existe para **experimentar, praticar, concluir e repetir**.

```text
Dataset
   ↓
Problema
   ↓
Perguntas
   ↓
Análise
   ↓
Evidências
   ↓
Conclusão
   ↓
Próximo projeto
```

> **Quanto mais ciclos completos de análise, maior a oportunidade de desenvolver raciocínio analítico.**



## 🚀 Evolução do laboratório

Este laboratório também funciona como um espaço para desenvolver habilidades além da execução técnica das análises.

### 🎥 Apresentações em vídeo

Quando o desenvolvimento dos projetos curtos estiver mais natural e consistente, pretendo começar a gravar **apresentações em vídeo de alguns projetos selecionados**.

A gravação não será um requisito para concluir cada projeto. A ideia é adicionar essa etapa gradualmente, sem comprometer a proposta de manter análises rápidas e de escopo reduzido.

Os vídeos terão como objetivo praticar:

- comunicação de resultados;
- storytelling com dados;
- apresentação de análises para diferentes públicos;
- síntese dos principais insights;
- explicação das decisões analíticas;
- comunicação de limitações e conclusões.

A estrutura das apresentações poderá seguir um fluxo simples:

```text
Contexto
   ↓
Problema
   ↓
Dados e abordagem
   ↓
Principais evidências
   ↓
Insights
   ↓
Conclusão
```

Os vídeos devem ser **curtos e objetivos**, priorizando a capacidade de explicar o raciocínio por trás da análise em vez de apresentar todos os detalhes técnicos.

No futuro, os projetos que possuírem apresentação poderão ser identificados na tabela principal do laboratório com um link para o respectivo vídeo.

> **O objetivo não é gravar todos os projetos, mas utilizar análises selecionadas para praticar a comunicação de dados.**
